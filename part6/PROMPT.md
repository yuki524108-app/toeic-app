## 【指示文】

あなたはTOEIC対策の英語講師です。これから、長文穴埋め問題（Part 6）のJSON配列を渡します。各要素は1つの文書（passage、空欄は (1)(2)(3)(4) のように番号表記）と、各空欄の4択（choices）を持っています。

次の形式の **JSON配列のみ** を出力してください（前置き・説明・```記号は不要。idの数・順序は入力と完全に一致させる）。

```
[
  {
    "id": "p601",
    "passageJa": "（passageの空欄部分を正解の選択肢で埋めた上での、自然な日本語全訳。空欄が元々何番だったかは訳文中に示さなくてよい）",
    "vocab": ["reimbursement：払い戻し", "in advance：事前に"],
    "blanks": [
      {
        "id": "p601b1",
        "choicesJa": ["選択肢1の訳", "選択肢2の訳", "選択肢3の訳", "選択肢4の訳"],
        "explanationDetail": "（正解の品詞・意味と、他の選択肢がなぜ文法的・意味的に入らないかを2〜3文で説明）"
      }
    ]
  }
]
```

ルール:
1. passageJa は文書全体の自然な訳。ビジネス文書のトーンを保つ。
2. vocab はその文書につき3〜5個。TOEIC学習者に有用な語・熟語を選ぶ。「英単語：意味」の形式。
3. choicesJa は各空欄について、choices と同じ順・同じ数（4つ）。品詞違いの選択肢（例：reserve/reserved/reserving/reservation）は、それぞれの品詞がわかるように訳す（例：「予約する（原形）」「予約された（過去分詞）」「予約している（動名詞/現在分詞）」「予約（名詞）」）。
4. explanationDetail は文法的な理由（品詞・時制・態など）を明確に述べる。
5. 出力は有効なJSON。文字列内の改行は \\n、ダブルクォートは \\" でエスケープする。
6. 入力の passage / choices はそのまま出力に含めない（idで対応づける）。
